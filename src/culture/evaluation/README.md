# Hindi CPT evaluation

Compares a **continued-pretrained (CPT)** checkpoint against its **untrained base
model** across the three dimensions of `docs/hindi_cpt_evaluation_plan.md`:

| Dim | What | Entry point |
|---|---|---|
| 1 | Language modeling (PPL / bits-per-byte) | `perplexity.py`, `run_perplexity.sh` |
| 2 | General English (MMLU/BoolQ/GSM8K/HumanEval) | `run_lm_eval.sh` (lm-evaluation-harness) |
| 3 | Hindi culture / idiom (4 benchmarks) | `run_eval.py`, `run_eval.sh`, `compare_results.py` |

Most of this README documents **Dimension 3** (the custom task module); Dim 1–2
are summarized under [Dimensions 1 & 2](#dimensions-1--2) below.

## Dimension 3 — Hindi culture / idiom

Four Hindi benchmarks. Three are scored with base-model log-likelihood (no
instruction following); IdiomCE is generated by the checkpoint and graded by an
**OpenAI judge**.

| Task | Measures | Native? | Format | Scoring | Primary metric |
|---|---|---|---|---|---|
| `mabl` | Figurative-meaning inference | ✅ native | 2-choice | log-likelihood | `acc_norm` |
| `milu` | India cultural-knowledge exam QA | ✅ native | 4-choice MMLU-style | log-likelihood (letter) | `acc` |
| `global_piqa` | Cultural physical commonsense | ✅ native | 2-choice | log-likelihood | `acc_norm` |
| `idiomce` | En→Hi idiomatic translation | ✅ native idioms | generation | OpenAI judge (1–5) | `idiom_score_mean` |

MC tasks report both `acc` (raw summed log-prob arg-max) and `acc_norm`
(length-normalized) as in the EleutherAI lm-eval-harness; the length-normalized
number is the fair one when options differ in length (MABL / Global PIQA).

## Data (local-file-first)

> **Exact download commands** (verified HF ids, file paths, `curl`/`huggingface-cli`
> lines, and schema caveats) are in
> [`docs/plans/eval_benchmarks_download.md`](../../../docs/plans/eval_benchmarks_download.md).
> The summary below is the schema each loader expects.

`milu` and `global_piqa` fall back to HuggingFace when no local path is given.
`mabl` and `idiomce` have no clean HF release, so a local file is **required**.
Put files under `data/eval/hi/` (or point the `*_path` flags anywhere).

### `mabl` — CSV/TSV, Fig-QA schema
Download the Hindi split from the MABL repo
(`github.com/simran-khanuja/Multilingual-Fig-QA`, the `hi` language file).
Columns (aliases accepted): `startphrase, ending1, ending2, labels` where
`labels ∈ {0,1}` is the index of the correct ending.
```csv
startphrase,ending1,ending2,labels
जीवन मीठा गुलकन्द है।,जीवन अच्छा है।,जीवन बुरा है।,0
```

### `milu` — HF `ai4bharat/MILU` (config `Hindi`), or local json/jsonl/csv
Accepted fields: `question`; options as a list under `options`/`choices` **or**
`option1..option4`; answer under `answer`/`target`/`label` (letter, index, or
option text). Optional `domain`/`subject`. For few-shot without leakage, pass a
separate validation file via `--milu_fewshot_path`.

### `global_piqa` — HF `mrlbenchmarks/global-piqa-nonparallel` (config `hin_deva`), or local TSV
Columns: `prompt, solution0, solution1, label` (`label ∈ {0,1}`).
```tsv
prompt	solution0	solution1	label
खीर बनाने के लिए	चावल, पानी और चीनी उबालें।	चावल, तेल और चीनी उबालें।	0
```

### `idiomce` — JSONL (reference-less judging)
IdiomCE's own set is unreleased, so **build it from the project's English idiom KB**
with `build_idiomce_eval.py` (procedure documented in
[`docs/plans/eval_benchmarks_download.md`](../../../docs/plans/eval_benchmarks_download.md) §4):
```bash
python -m culture.evaluation.build_idiomce_eval \
    --idiom_path culture/data/idioms/en/idioms_merged_llm_formatted_figurative_only.jsonl \
    --output_path data/eval/hi/idiomce_hi.jsonl \
    --num_samples 500 --model gpt-4o --provider openai
# add --add_reference for an (LLM-generated, non-gold) Hindi reference
```
Output schema (one English idiom sentence per line; `reference`/`idiom_en` optional
— a reference makes the judge reference-guided):
```json
{"source": "Don't count your chickens before they hatch.", "idiom_en": "count your chickens before they hatch", "reference": "..."}
```

## Run

Both checkpoints + delta in one shot:
```bash
BASE_MODEL=/path/to/Qwen3.5-9B \
CPT_MODEL=/path/to/qwen3p5-9b-hi-cpt \
DATA_DIR=data/eval/hi JUDGE_MODEL=gpt-4o \
bash src/culture/evaluation/run_eval.sh
```

Or one checkpoint directly:
```bash
python -m culture.evaluation.run_eval \
    --model_path /path/to/qwen3p5-9b-hi-cpt --run_name cpt \
    --tasks mabl,milu,global_piqa,idiomce \
    --mabl_path data/eval/hi/mabl_hi.csv \
    --global_piqa_path data/eval/hi/global_piqa_hi.tsv \
    --idiomce_path data/eval/hi/idiomce_hi.jsonl \
    --judge_model gpt-4o \
    --output_dir results/hi/cpt
```

Quick smoke test: add `--limit 16 --no_judge`.

Compare:
```bash
python -m culture.evaluation.compare_results \
    --base results/hi/base/summary.json --cpt results/hi/cpt/summary.json
```

## Output

Per task: `results/<run>/<task>.json` (metrics + per-example records:
gold/pred/log-probs for MC, hypothesis + judge verdict for IdiomCE).
Per run: `results/<run>/summary.json`. `compare_results.py` prints the
base→CPT delta on each task's primary metric — the headline you want is a
**positive delta on all four** (esp. `mabl` and `idiomce`, the figurative ones),
which shows the CPT injected Hindi cultural-figurative competence.

## Dimensions 1 & 2

### Dimension 1 — perplexity / bits-per-byte (`perplexity.py`)

PPL + tokenizer-agnostic BPB over a corpus, via a sliding-window rolling NLL on
the same `HFModel`. Lower is better.

```bash
# both checkpoints, Hindi held-out (adaptation) + WikiText-103 (retention):
BASE_MODEL=/path/to/Qwen3.5-9B CPT_MODEL=/path/to/qwen3p5-9b-hi-cpt \
HELDOUT_PATH=data/eval/hi/hi_proverbs_heldout.jsonl \
bash src/culture/evaluation/run_perplexity.sh

# one checkpoint / one corpus directly:
python -m culture.evaluation.perplexity --model_path /path/to/ckpt --run_name cpt \
    --data_path data/eval/hi/hi_proverbs_heldout.jsonl --output_dir results/hi/cpt/ppl_hi
```
Writes `perplexity.json` with `ppl`, `bits_per_byte`, token/byte counts. The
Hindi corpus is `{"text": ...}` JSONL; WikiText is pulled with `--hf_dataset`.

> **Contamination:** the held-out corpus must be **excluded from CPT training**
> (reserve it before training, or use an independent Hindi corpus) — otherwise the
> adaptation number is contaminated. See the module docstring.

### Dimension 2 — general English (`run_lm_eval.sh`)

MMLU (0-shot), BoolQ (0-shot), GSM8K (8-shot CoT via `gsm8k_cot`), HumanEval
(0-shot, `--confirm_run_unsafe_code`) + WikiText, on both checkpoints via
`lm-evaluation-harness`. This is a **forgetting check** — expect Δ ≈ 0.

```bash
pip install lm-eval
BASE_MODEL=/path/to/Qwen3.5-9B CPT_MODEL=/path/to/qwen3p5-9b-hi-cpt \
bash src/culture/evaluation/run_lm_eval.sh
```
Results land under `results/hi/{base,cpt}/lm_eval/<task>/`.

## Notes / caveats

- **Scoring choice.** MABL/Global PIQA compare full-sentence options → use
  `acc_norm` (length-normalized). MILU scores a single answer letter (MMLU-style)
  → `acc == acc_norm`; `acc` is reported as primary.
- **Templates** are explicit constants at the top of `tasks.py` (Hindi by
  default) — tune them there; keep base and CPT identical for a fair delta.
- **IdiomCE is reference-less by design** (one idiom → many valid renderings), so
  a judge is required; single-answer 1–5 grading, `temperature=0`. For a
  pairwise base-vs-CPT preference with order-swapping, extend `judge.py`.
- **`flash_attn`**: the scorer uses `attn_implementation="sdpa"` — the Qwen 3.5
  FA2 path crashes on the optional `s_aux` attention sink (same gotcha as CPT).
- **No native Hindi idiom *cloze/MC*** benchmark exists off-the-shelf (unlike
  Chinese ChID); MABL is the closest, and a purpose-built muhavare set from the
  project's own pipeline would fill that gap.
